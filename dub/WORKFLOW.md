# 操作手册（给 AI agent 照着跑）

**目标**：一条固定素材 → AI 按素材时长写 N 份文案 → 每条文案出一条成片。
素材拍一次，成片数 = 文案数；配音、字幕、合轨全自动。

本文件是**可执行的说明书**：每个命令都能直接粘、输出长什么样、读到哪个数该做什么、失败怎么回退。

---

## 0. 目录与文件契约

```
工作目录/
├── 素材.mp4                 ← 唯一素材，全程不改
├── 话术.wav + 话术.txt      ← 克隆音色参考（5~15s 干净人声 + 对应文字），一次准备长期复用
├── 文案/
│   ├── v1_卖点.txt          ← AI 产出，一行一句
│   ├── v2_场景.txt
│   └── v3_价格.txt
└── 成片/
    ├── 素材_v1_卖点.mp4     ← 自动命名 <素材名>_<文案名>.mp4
    └── ...
```

脚本位置：`dub/dub.sh`（单份）、`dub/batch.sh`（批量）。

| 脚本 | 作用 |
|---|---|
| `dub.sh 视频 文案.txt --plan` | 只体检：量时长、判字数、写 `<视频>_copy.txt/_copy.srt`，不出片 |
| `dub.sh 视频 文案.txt --probe` | 试合成：真跑 TTS，报每段落点/时长，不出片 |
| `dub.sh 视频 文案.txt --out x.mp4` | 出片 |
| `batch.sh 视频 文案/ [--plan\|--probe]` | 上面三种模式对整批文案循环 |

## Agent 的执行顺序（固定 6 步）

```
① 量素材  → ② 写 N 份文案 → ③ 整批体检 → ④ 改到全贴合 → ⑤ 试合成 → ⑥ 批量出片 + 验收
```

### ① 量素材：拿到「可用秒数」和「建议字数」

先随便给一份文案（已有的参考话术即可）跑一次 `--plan`：

```bash
dub/dub.sh 素材/产品介绍.mp4 话术.txt --plan
```

输出（真实）：

```
视频 20.00s ｜ 可用 19.50s ｜ 文案 129 字 8 句
建议字数 62~76（rate 3.5 字/秒）
配音 34.30s ｜ 语速 x1.15 ｜ 句间 0.30s ｜ 片尾余 0.00s
⚠ 超时 16.90s，约需砍 69 字（或加 --allow-drop 让它自动均匀抽句）
```

**Agent 只取两行**：

- `可用 XX.XXs` → 配音总时长上限（= 视频时长 − 片头 0.3 − 片尾 0.2）
- `建议字数 A~B` → 每份文案的字数区间，写文案时卡在这个区间内就基本一次过

这两个数只跟素材有关，**量一次，整批复用**，不用每份文案都量。

### ② 按「可用秒数 + 建议字数」写 N 份文案

把第 ① 步的两个数丢给 AI，一次出 N 份不同切入点的文案。**文案格式硬约束**（脚本按此切句配对）：

| 规则 | 原因 |
|---|---|
| **一行一句**，句子之间用换行（或 `。？！；`） | 换行/这些标点是切句点，每句配一次停顿 |
| 单句 **≤ 20 字** | 超过 20 字会被自动按逗号拆成两条字幕，容易切碎 |
| 全文落在**建议字数区间** | 低于区间→片尾空；高于→直接报超时不出片 |
| 纯口播文本，不要 emoji、`*`、`#`、markdown、圆括号注释 | 标点会被清掉朗读，符号会念出来或卡顿 |
| 数字/英文写常见形式（`jbl`、`3.5` 可，别用 `¹²³` 这种） | TTS 发音稳定性 |

文案生成提示词（直接复制给模型）：

```
你是短视频口播文案。素材时长 {可用秒数} 秒，全文必须控制在 {A}~{B} 个汉字（含数字英文），
一行一句，每句不超过 20 字，不要 emoji、不要 markdown、不要括号注释。
围绕以下信息写 {N} 份不同切入点的版本（如：卖点型 / 场景型 / 价格型 / 对比型），
每份单独输出为一个 .txt 文件内容，第一行就是第一句。
信息：{把产品资料/评论/卖点原文贴这里}
```

产出落到 `文案/` 下，文件名即版本名，最终成片名取它：

```bash
文案/v1_卖点.txt   v2_场景.txt   v3_价格.txt
```

### ③ 整批体检（出片前必做）

```bash
dub/batch.sh 素材/产品介绍.mp4 文案/ --plan
```

输出：

```
▸ [1/3] v1_卖点
    视频 20.00s ｜ 可用 19.50s ｜ 文案 66 字 5 句
    建议字数 62~76（rate 3.5 字/秒）
    配音 17.90s ｜ 语速 x1.00 ｜ 句间 0.70s ｜ 片尾余 0.00s
    ✓ 长度贴合
▸ [2/3] v2_场景
    ...
    ⚠ 偏短，片尾会空 6.0s，建议补 17~22 字内容
▸ [3/3] v3_价格
    ...
    ⚠ 超时 16.90s，约需砍 69 字
------------------------------------------------------------
体检完成：可 1 份 / 需改 2 份
```

**Agent 的判定逻辑（照这个改，不要猜）**：

| 看到 | 含义 | 动作 |
|---|---|---|
| `✓ 长度贴合` | 配音刚好铺满 | 收，不动 |
| `⚠ 超时 X 秒，约需砍 Y 字` | 装不下 | 删/合并句子合计约 Y 字，**优先删重复卖点，不要掐半句** |
| `⚠ 偏短，片尾会空 Z 秒，建议补 N~M 字` | 差内容 | 补 N~M 字（加一个卖点/场景/疑问句） |

改完**重跑 ③**，直到 `需改 0 份`。别跳过这步直接出片 —— 超时的文案出片会直接报错退出。

`--plan` 会顺手写 `<视频>_<文案>_copy.txt` + `_copy.srt`（带停顿的字幕时间轴，可导入剪辑软件核对）。

### ④ 试合成：用实测时长确认落点（推荐，几秒钟）

```bash
dub/batch.sh 素材/产品介绍.mp4 文案/ --probe
```

```
视频 20.00s ｜ 保留 4/4 句 ｜ 配音 17.28s ｜ 句间 0.63s ｜ 落点 19.63s
  段1(0:00:00.47→0:00:04.30, 3.83s): 全球十大音响品牌 jbl
  段2(0:00:04.93→0:00:08.27, 3.34s): 现在属于哈曼卡顿旗下。
```

Agent 检查：**落点 ≤ 视频时长**（这里是 19.63 ≤ 20 ✓），句数 = 文案行数（`保留 4/4 句`）。
落点超了说明实际语速比估算慢，回 ③ 再砍几个字。

### ⑤ 批量出片

```bash
dub/batch.sh 素材/产品介绍.mp4 文案/ --voice 话术 --out 成片/
```

```
▸ [1/3] v1_卖点
    已生成: 成片/产品介绍_v1_卖点.mp4
    ✓ 成片/产品介绍_v1_卖点.mp4
...
完成：成功 3 条 / 失败 0 条
```

每条做的事：逐句克隆 TTS → 按落点拼连续旁白 → 生成 ASS → ffmpeg 烧字幕合轨。
默认静音原声；要保留环境音加 `--keep-audio`（原声 0.35）。
返回码：全成功 `0`，有失败 `1`，参数错 `2` —— 用返回码判批处理结果。

### ⑥ 验收（必查，不看画面也要查文件）

```bash
for f in 成片/*.mp4; do
  printf '%s  %s\n' "$(ffprobe -v error -show_entries format=duration -of csv=p=0 "$f")s" "$f"
done
```

三条硬指标：

1. 每份文案对应一个成片，文件名 `<素材名>_<文案名>.mp4`
2. 时长 ≈ 素材时长（±0.5s）
3. 文件非空（`-s` 判断），否则说明渲染失败但返回 0（罕见，以 ffprobe 为准）

## 完整可复制的端到端脚本（AI 直接跑）

```bash
set -euo pipefail
DUB=dub
VIDEO=素材/产品介绍.mp4
COPIES=文案

# ① 量素材（拿建议字数区间）
$DUB/dub.sh "$VIDEO" 话术.txt --plan | tee /tmp/measure.txt
#   → 人工/AI 从这里读 可用秒数 与 建议字数

# ② 此时把建议字数交给 AI 生成 N 份 .txt 放进 文案/

# ③ 整批体检 → 读「需改 N 份」，改到 0
$DUB/batch.sh "$VIDEO" "$COPIES" --plan

# ④ 试合成确认落点
$DUB/batch.sh "$VIDEO" "$COPIES" --probe

# ⑤ 出片
$DUB/batch.sh "$VIDEO" "$COPIES" --voice 话术 --out 成片/

# ⑥ 验收
ls -l 成片/*.mp4
```

迭代只有一条路径：**改 `文案/*.txt` → 重跑 ③ 或 ⑤**。素材、音色、字幕样式、字体都不动。

## 出错怎么办（对照表）

| 报错/现象 | 原因 | 修法 |
|---|---|---|
| `文案超时 X 秒（约多 Y 字）：… 建议 A~B 字` | 文案字数超了 | 删/合并约 Y 字，或加 `--allow-drop`（自动均匀抽句，效果需自己验） |
| `⚠ 偏短，片尾会空 Z 秒` | 内容不够 | 补 Z×3.5 个字左右 |
| 逐条落点挤在一起/字幕一闪而过 | 句子切太碎 | 把 2~3 个短句合成一句 |
| 某句念得特别赶 | 单句过长 | 拆成两句（会多一个句间停顿） |
| 数字/英文念错 | TTS 读法 | 改成中文读法（`3.5` → `三点五`） |
| `视频文件不存在或为空` | 路径错 | 用**绝对路径**或确认 cwd |
| 落盘 `_copy.*` 互相覆盖 | 单份 `dub.sh --plan` 写在视频旁边 | 批量用 `batch.sh`（会自动按文案名分开命名） |
| 想排查中间产物 | 工作目录默认删除 | `VDUB_KEEP=1 dub/dub.sh …` 保留 `/tmp/vdub_*` |
| 音色没准备好 | 缺 `~/话术.wav` 或同名 `.txt` | 用 `--ref 参考.wav --ref-text 文字` 临时克隆，跑完自动清 |

## 参数速查

| 参数 | 默认 | 说明 |
|---|---|---|
| `--voice` | 话术 | 音色名（`~/<名>.wav` + 同名 `.txt`） |
| `--ref` / `--ref-text` | — | 临时克隆参考音频/文本，跑完清理 |
| `--rate` | 3.5 | 估算字速（字/秒）：口播快给 4.0~4.5，慢给 3.0 |
| `--max-gap` | 1.2 | 句间停顿上限（秒），文案偏短时自动拉长到它 |
| `--clone-speed` | 1.0 | 克隆引擎语速倍率 |
| `--plan` / `--probe` | 关 | 体检 / 试合成，均不出片 |
| `--allow-drop` | 关 | 允许程序自动均匀抽句（默认拒绝：砍哪句由 AI/人决定） |
| `--keep-audio` | 关 | 原声做背景，音量 0.35 |
| `--ss` / `--trim-end` | 0 | 掐头 / 去尾（秒） |
| `--font` | Noto Sans CJK SC Bold | 字幕字体 |
| `--out` | `<素材>_<文案>.mp4` | batch：目录；dub：单文件路径 |

节奏是怎么排的（不需要你算，但出错时要看得懂）：
逐句配音取实测时长 → 句间停顿在 `max-gap` 内均匀拉伸 → 仍有余量则起播点后移（≤1.5s）→ 还剩就留片尾并报「偏短」。
语速只在 **0.88~1.15 倍**内微调整段，**绝不删句**。

## 路线 B：EDL → 静音字幕片（不走 TTS）

`dub.lua` 是「文案 → 配音 → 对时长」；如果不需要 AI 配音，只要按画面剪辑 + 烧字幕，
走 `render.sh` 这条更短的：

```bash
# 1) 文案 → EDL（match.lua 按画面阶段窗口挑 in/out）
luajit dub/match.lua --text 文案.txt --shot dub/shot/IMG_0195.json --out edl.json

# 2) EDL → 成片（逐段切 → concat → 烧 ASS，输出丢原声）
bash dub/render.sh edl.json ~/dub/out.mp4
```

`render.sh` 只认两个东西：EDL 的 `src` 与每项 `in/out/text/dur`。
字幕按 EDL 顺序**从头累加**排时间轴，与画面段一一对应。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--keep-audio` | 关（`-an` 丢原声） | 保留素材原声，AAC 160k 单声道 |
| `--crf=N` | 20 | 成片质量 |
| `--preset=` | medium | x264 预设 |
| `--w=` / `--h=` | 1080 / 1920 | 输出尺寸（竖屏默认） |

两个坑（已修）：

1. **一次 `filter_complex` 切 13 段 1080p hevc 会 OOM 被杀** —— 现在逐段
   `-ss/-to` 快 seek 转码（一次只解一路），写 `-crf 18` 中间件，再 `concat` + 烧字幕。
2. **手机素材 ffprobe 报 1920×1080 但带 `rotation=-90`**，真实是竖屏 1080×1920。
   按 `width/height` 排 `pad` 会得到上下大黑边，所以默认按竖屏出。

## 依赖

`luajit`、`ffmpeg`/`ffprobe`、克隆 TTS（cosyvoice 默认）或 `sherpa-onnx`（kokoro 引擎）。
